# MiniDispatch - 多机器人智能调度系统

一个基于 **C++** 实现的简易多机器人调度 Demo。系统以字符地图为载体,模拟「任务下发 - 路径规划 - 机器人移动 - 任务完成」的完整闭环,是学习**数据结构(BFS)**、**面向对象设计**与**调度算法**的入门级参考实现。

## 项目简介

MiniDispatch 是一个控制台程序(`main.exe`),演示了在多台机器人的场景下如何完成任务调度:

- 从文本文件加载一张**栅格地图**,地图中包含墙体、空地、任务点、充电站等元素;
- 程序扫描地图上的任务点,为每个任务点生成 `Task`;
- 创建 `Robot` 实例,通过 **BFS 广度优先搜索**规划到目标点的最短路径;
- 机器人沿路径逐格移动,每次移动消耗电量,最终到达任务点完成任务。

> 定位:教学 / 原型演示项目,旨在用尽量简洁的代码讲清楚「地图 - 任务 - 调度 - 路径 - 执行」这条主线。

---

## 核心特性

- **地图加载与校验**:从文本文件读取地图,自动校验尺寸合法性,异常时抛出自定义异常;
- **任务点自动识别**:扫描地图中标记为 `T` 的格子,批量生成任务;
- **任务优先级**:任务支持 `LOW / MEDIUM / HIGH` 三级优先级;
- **机器人状态机**:机器人具备 `Idle / Moving / Working / Charging / RETURNING` 五种状态;
- **电量模拟**:机器人移动会消耗电量,低于阈值电量, 机器人选择充电而返还任务;
- **BFS 路径规划**:基于四方向 BFS 求取最短路径,并递归回溯还原路径;
- **对象所有权管理**:调度器使用 `std::unique_ptr` 持有机器人,并统一调度`Robot`,`Task`,`Map`。

### 模块依赖关系(简述)

```text
   Scheduler -------> Robot --------> Map / Task / Utils(bfs, point)
       |                                       ^
       |                                       |
       +----------> Task / Map                 |
   Utils(except) <------ 各模块(统一异常接口)
```
- 本项目分为**调度层 -> 执行层 -> 数据层**, 后续所有内容皆为按照此层次设计. 
- **Map / Task / Point / Power** 属于底层数据模型,不依赖上层;
- **Robot** 依赖 Map(路径判定)与 BFS(路径规划);
- **Scheduler** 同时持有 Task 队列与 Robot 列表,是调度逻辑的中心, 统一调度数据模型和行为模型;
- **Utils** 中的异常体系被各模块共用。

**为什么选择`Task`, `Power`, `Point` 三层数据?**
- `Task`负责任务相关属性, `Power`负责充电桩相关属性, `Point`负责机器人坐标位置
- 后续可对机器人, 充电桩, 任务等相关内容维护以及拓展
- 不同数据负责不同内容, 职责划分, 不会造成数据层的相互依赖

## 模块详解

### 1. Map 地图模块(`Map/`)

负责地图的加载、存储与查询。

| 方法 | 说明 |
| --- | --- |
| `Map(rows, cols)` | 按指定行列数初始化空网格 |
| `Load_map_from_file(path)` | 从文件读取地图,校验行列尺寸,越界抛 `Size_error`,文件缺失抛 `File_error` |
| `print_map()` | 将地图原样打印到控制台 |
| `is_walkable(x, y)` | 判定某格是否可通行(越界或 `#` 墙体不可通行) |
| `get_task_list()` | 扫描地图,返回所有标记为 `T` 的任务点坐标 |
| `get_power_list()` | 扫描地图,返回所有标记为 `C` 的任务点坐标 |
| `get_cell()` | 返回某一位置的地图数据 |

地图图例(来自 `map.txt`):

| 字符 | 含义 |
| --- | --- |
| `#` | 墙体,不可通行 |
| `.` | 空地,可通行 |
| `T` | 任务点 |
| `C` | 充电站 |

### 2. Task 任务模块(`Task/`)

描述一个待执行的调度任务。

- `Priority` 枚举:`LOW`(低)、`MEDIUM`(中)、`HIGH`(高);
- `Task` 结构体:由坐标 `(x_, y_)`、优先级 `type_`、完成标志 `done` 组成;

### 3. Robot 机器人模块(`Robot/`)

描述一台具备状态和移动能力的机器人。

- `State` 枚举:`Idle`(空闲)、`Moving`(移动中)、`Working`(工作中)、`Charging`(充电中)、`RETURNING`(返航中);
- 核心成员:编号 `id_`、坐标 `(x_, y_)`、电量 `power_`(初始 100)、路径 `path_`、状态 `state_`;
- 关键方法:
  - `decide_path(task, map)`:调用 BFS 规划到目标点的最短路径;无路可达时抛 `Path_error`;
  - `moving()`:沿路径前进一格,电量 -10,状态置为 `Moving`;
  - `get_msg()`:输出机器人当前信息(ID / 坐标 / 电量 / 状态);
  - `arrived_task_pos()`:到达目标点后进行执行任务并判断是否完成任务
  - `receive_task`: 接受由调度器传来的任务, 并以原始指针的方式指向!
  **为什么这样设计?** 在本项目中, 仅有`scheduler`调度`Robot`, `Task`; `Robot`不能独占所有权`Task`. 且该项目中`Robot`不负责其生命周期, 因此使用原始指针也不需要`delete`

  - `step()` 机器人状态机, 由何种状态预测可能进行的下一步行为. (关于为什么这样设计,请见 [6.3 核心设计决策](#架构设计))
  - `turn_to_dead()`: 预测机器人是否因没电而宕机
  - `tell_power_threshold()`: 判断机器人电量是否低于阈值, 低于阈值后丢回任务
  - `decide_charge()`: 机器人判断遇到充电机后, 重新规划`最优路线`
  **如何实现最优?** 通过遍历不同充电桩位置, 记录从当前位置到不同终点位置的长度, 选择最优路线的最短路线
 - `arrived_power_pos()`: `与arrived_task_pos()`类似, 见上
 - `finished_task()`: 判断是否完成任务
  - `charging_and_finished_power()`: 判断是否充满电量
### 4. Scheduler 调度模块(`Scheduler/`)

系统的调度中枢。

- 内部持有任务队列 `task_list_` 与机器人列表 `robot_list_`(以 `std::unique_ptr<Robot>` 管理所有权);
- `assign_task()`:从任务队列中取出一个**未完成**的任务,按优先级 `HIGH > MEDIUM > LOW` 优先返回;
- `step(map)`:驱动一次调度——对每个处于空闲态的机器人,分配一个任务并为其规划路径。
- `step():` 对行为层以及数据层进行调度, 第一阶段分配任务, 第二阶段机器人行动 并打印输出日志信息
- `all_done()`,`all_dead()`: 统计任务完成以及机器人宕机数量
- `print_statistics()`: 数据统计以及打印
- `print_all_robot_msg()`,`print_all_task_msg()`,`print_map_with_robot`: 打印输出数据层信息

### 5. Utils 工具模块(`Utils/`)

公共的基础设施。

- `point.h`:坐标结构 `Point { int x_; int y_; }`;
- `bfs.h / bfs.cpp`:
  - `bfs(map, x, y, target_x, target_y)`:四方向 BFS,求起点到目标点的最短路径;
  - `recursion(Node, k, ans)`:依据 BFS 节点记录的父索引,递归回溯还原路径;
  - 辅助结构 `BfsNode { int x_; int y_; int parent_; }`;
- `except.h`:统一异常体系

  ```text
  std::runtime_error
       └── Error                # 异常基类
             ├── Size_error     # 地图尺寸不合法
             ├── File_error     # 文件路径错误
             └── Path_error     # 路径不可达
  ```

## 架构设计

### 6.1 架构总览

> 建议从整体视角描述系统的分层结构,例如:
> 系统调用层次: `Scheduler`
> 执行层: `Robot`
> 数据模型层: `Task`, `Power` 
> 基础工具层: `Map`, `Utils`

### 6.2 模块依赖与解耦设计

> `Map`模块作为静态数据层面独立
> - 为什么 Scheduler 采用 `std::unique_ptr` 管理 Robot, Scheduler独占Robot所有权, 与`Task`, `Power`层面统一调度, 后续也可进行拓展;

### 6.3 核心设计决策

> - 关于路径选择: **Astar**, 作为小地图且为了快速开发,选择使用**BFS**; 但是我们于*2026-9-2*优化算法采用了`A*`算法.**为什么?**
- **BFS**通常更加复杂且地图较大时候遍历时间更加长, 性能优化远不如**Astar**
- 后续我们更加方面拓展动态障碍规划路径

> - 机器人**状态机**的设计: 
> 1. 将机器人状态以及该状态下执行任务分开, 如`Working`状态下行为目前有且仅有`判断任务是否完成`以及`完成任务`两种方式. 即可观测状态下可预判进行何种行为 **为什么这样设计:** 初始设计时, 机器人执行某项任务后, 判定会处于何种状态. 如`Moving`动作, 机器人可能处于在`Moving`(完成任务时候进行的动作)亦或者`Returning`(返回充电桩时候的动作), 即一个动作无法预测机器人处于何种状态. 
> 2. 同时, 如此设计下, 还可以进行状态的切换: 机器人处于何种状态 -> 可预测执行何种行为 -> 何种行为会导致何种状态; 相反, 初始设计时, 机器人执行何种任务 ->x 无法预测处于何种状态 ->x 无法进行状态切换
> - **优先级调度**策略: 任务调度优先级: `High` > `Mediumn` > `Low`; 设计思路: 按照优先级优先遍历高等级且未分配任务, 同等优先级未进行处理
> - 自定义**异常体系**: 主要负责`文件处理失败`, `机器人放置失败`, `地图初始化失败`问题 

### 6.4 扩展方向与后续演进

> 建议展望未来可扩展的能力,例如:
> - 多机器人避碰与路径冲突检测;
> - 电量约束下的充电调度策略;
> - 动态任务插入与重规划;
> - 引入 A* / 时间窗等更优算法; √
> - 多线程/多进程化改造。

# 算法设计
## A*算法关键设计
```cpp
for(int i = 1;i<=4;i++) {
    ...
    if(cur.g_ != cost_so_far[next_x][next_y]) continue;
    // 优化点 : 当长路径被替换时, frontier队列可能存在长路径, 后续可能会继续弹出剩余路径, 造成不必要的浪费
    if(!map.is_walkable(next_x, next_y)) continue;

    if(cost_so_far[next_x][next_y] == -1 || next_g_ < cost_so_far[next_x][next_y]) {

    cost_so_far[next_x][next_y] = next_g_;
    ...
    } else {
        continue;
    }
}
```
**优化点为什么这样设计?**
*在Astar算法中,`cur.g_`总是大于等于cost_so_far[next_x][next_y]的; 但是如果cur.g_更新后, cost_so_far[next_x][next_y]等于cur.g_;但是当之前的长路径被弹出后, 依然会进行后续的逻辑, 会造成浪费.*

## 运行流程

`main.cpp` 演示了从加载地图到机器人移动的完整链路:

```text
① 创建 10x30 地图(或者采用map.txt测试地图),从 map.txt 加载(失败则捕获异常)
② 打印地图,测试 is_walkable 通行判定
③ 扫描任务点 T,生成 Task 并打印任务状态
④ 创建机器人 Robot(1, 1, 1)
⑤ 调用 BFS 打印最短路径,并让机器人 decide_path 决策路径
⑥ moving() 沿路径移动(耗电),get_msg() 输出机器人状态
```

当前实现为**单轮演示**逻辑,`Scheduler::step()` 已具备循环调度的雏形,可在此基础上扩展为持续运行的多机器人调度循环。

## 构建与运行

### 编译

在项目根目录执行(需已安装 `g++`):

```bash
g++ -I main.exe main.cpp \
    Map/map.cpp \
    Task/Task.cpp \
    Robot/robot.cpp \
    Scheduler/scheduler.cpp \
    Power/power.cpp
    Utils/bfs.cpp
```

> 如需调试符号,追加 `-g`;如需启用优化,追加 `-O2`。

### 运行

```bash
./main.exe
```

运行结果将依次输出:地图快照、通行判定结果、任务列表、BFS 路径、机器人移动过程与最终状态。

## 地图文件说明

- 地图为纯文本,每行字符数即列数,行数即行数(需与构造时指定尺寸匹配,否则抛出 `Size_error`);
